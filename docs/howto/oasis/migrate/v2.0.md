# Migrate to NOMAD 2.0

## Elasticsearch Migration (v7.17 to v9.5)

Starting with **NOMAD 2.0**, the default Elasticsearch image has been changed from **Elasticsearch 7** to **Elasticsearch 9** (default container version `9.5.0`).

Because Elasticsearch 9 cannot read indices created with Elasticsearch 7 due to major Lucene version changes, existing data cannot be read directly from an old Elasticsearch 7 volume.

There are two migration options:

1. **Option 1: Reindex data directly from ES7 to ES9 (running two containers)** — Uses the temporary `docker-compose.es7.yaml` overlay to run ES7 alongside the main ES9 service and copy the existing index through Elasticsearch's remote `_reindex` API. This is usually faster because it copies indexed documents without reading archive files.
2. **Option 2: Start with a fresh ES9 index and reindex uploads** — Rebuilds the search index from MongoDB and the archive files (`.volumes/fs`), which are NOMAD's source of truth. This is simpler but can be considerably slower because NOMAD must read and index every upload again. ES7 and the overlay are not needed for this option.

**Option 1 requires Python 3 on the host** (not inside the containers) and uses only its standard library. Check with `python3 --version`. If Python 3 is unavailable, use [Option 2](#option-2-start-with-a-fresh-es9-index-and-reindex-uploads), which does not require Python on the host. Complete the shared preparation steps below before following either option.

As a rough benchmark, migrating a project with 10,000 perovskite entries took about **1 minute with Option 1** and **15 minutes with Option 2** on the same machine. Actual times depend on your data and hardware.

Both options keep the NOMAD app and workers stopped during indexing. The main `elastic` service uses its permanent ES9 volume throughout, so no volume switch is needed after migration.

!!! note
    Previously, NOMAD maintained a separate materials index (`nomad_materials_v1` / `nomad_oasis_materials_v1`). This index is deprecated and dropped in NOMAD 2.0. **Only the entries index (`nomad_oasis_entries_v1` or `nomad_entries_v1`) needs to be migrated.**

### Prepare for Either Migration Option

Run all commands from your Oasis distribution directory. Keep the same Compose project name throughout the migration; if you normally pass `-p`, use it with every command below. Keep the same shell session so that the `INDEX` variable remains available.

1. **Back up MongoDB and file storage** while your existing installation is still running:

    ```bash
    bash scripts/backup-mongo.sh
    ```

    Verify the dump and back up `.volumes/fs`. See [Backups](../administer.md#backups).

2. **Record the effective entries index name** before stopping the old app. Configuration overrides can change it from the value in `configs/nomad.yaml`:

    ```bash
    INDEX=$(docker compose exec -T app python -c \
      'from nomad.config import config; print(config.elastic.entries_index)')
    printf 'Entries index: %s\n' "$INDEX"
    ```

    It is normally `nomad_oasis_entries_v1` for an Oasis or `nomad_entries_v1` if unset. If you open a new shell later, set `INDEX` to the recorded value before continuing.

3. **Stop the old stack before updating its Compose configuration**:

    ```bash
    docker compose down
    ```

    Do not pass `-v` or remove database volumes. Keep the app and workers stopped until indexing is complete.

4. **Update your distribution to NOMAD 2.0**, including its images, configuration, `docker-compose.yaml`, and `docker-compose.es7.yaml`. Follow the [distribution release notes](https://github.com/FAIRmat-NFDI/nomad-distro-template/releases){:target="_blank" rel="noopener"} and preserve your Oasis-specific configuration and plugins.

    The updated main Compose file already configures:

    - The `elastic` service with image `docker.elastic.co/elasticsearch/elasticsearch:9.5.0` and `xpack.security.enabled=false`.
    - A separate ES9 volume, `nomad_oasis_elastic_9`, mounted by `elastic`.
    - `NOMAD_ELASTIC_VERSION: 9` in the NOMAD services.

    Keep your entries index name unchanged. If you customized volume names, preserve the MongoDB volume and ensure ES9 uses a new, separate volume. **Never mount the ES7 data volume in ES9.** Pull the updated images:

    ```bash
    docker compose pull
    ```

Choose one of the following options.

### Option 1: Reindex Data Directly from ES7 to ES9

The `docker-compose.es7.yaml` file is a migration overlay used together with the main Compose file. It adds an `elastic7` service using Elasticsearch `7.17.28` and the existing `nomad_oasis_elastic` volume, and allows the main ES9 service to reindex from `elastic7:9200`. Both services share the main Compose network. Elasticsearch ports remain internal to Docker.

The ES7 volume is declared external: Compose fails if it does not exist instead of silently creating an empty source volume. If your old volume has a different name, update `volumes.elastic7.name` in the overlay first. If you used a customized ES7 image or configuration, carry the required settings into `elastic7` as well.

#### 1. Start Only ES7 and ES9

```bash
docker compose -f docker-compose.yaml -f docker-compose.es7.yaml pull elastic7
docker compose -f docker-compose.yaml -f docker-compose.es7.yaml \
  up -d --wait --wait-timeout 360 elastic elastic7
```

Do not start the app or workers yet. The destination entries index must not already exist in ES9; if an earlier migration attempt created it, resolve that partial migration before continuing.

HTTP requests run through the Elasticsearch containers, so no host port bindings are needed.

#### 2. Create the ES9 Index, Reindex, and Verify

Run the entire block below in the same shell where you set `INDEX`. It copies the settings and mapping, creates the destination index, reindexes from ES7, and verifies the response and document counts. If you use a custom Compose project name, add `"-p", "your-project-name"` to the `compose` list after `"compose"`.

```bash
python3 - "$INDEX" <<'PY'
import json
import subprocess
import sys
import tempfile
from pathlib import Path
from urllib.parse import quote

index = sys.argv[1]
if not index:
    sys.exit("INDEX is empty. Set it to the recorded entries index name first.")
index_path = quote(index, safe="")
compose = [
    "docker", "compose",
    "-f", "docker-compose.yaml", "-f", "docker-compose.es7.yaml",
]


def request(service, path, method="GET", body=None):
    command = compose + [
        "exec", "-T", service, "curl", "-fsS",
        "-X", method, "http://localhost:9200/" + path,
    ]
    if body is not None:
        command += ["-H", "Content-Type: application/json", "--data-binary", "@-"]
    response = subprocess.run(
        command,
        input=json.dumps(body) if body is not None else None,
        stdout=subprocess.PIPE,
        text=True,
        check=True,
    )
    return json.loads(response.stdout)


print("Reading ES7 settings and mapping...", flush=True)
settings = request("elastic7", index_path + "/_settings?flat_settings=false")
mapping = request("elastic7", index_path + "/_mapping")
source_settings = settings[index]["settings"]["index"]

print("Creating the ES9 index...", flush=True)
created = request("elastic", index_path, method="PUT", body={
    "settings": {
        "number_of_shards": int(source_settings.get("number_of_shards", 1)),
        "number_of_replicas": 0,
        "analysis": source_settings.get("analysis", {}),
    },
    "mappings": mapping[index]["mappings"],
})
if created.get("acknowledged") is not True:
    sys.exit("Index creation was not acknowledged. Inspect ES9 before continuing.")

print("Reindexing from ES7 to ES9; waiting for completion...", flush=True)
result = request(
    "elastic", "_reindex?wait_for_completion=true&refresh=true",
    method="POST", body={
        "source": {
            "remote": {"host": "http://elastic7:9200"},
            "index": index,
            "size": 100,
        },
        "dest": {"index": index},
    },
)
response_path = Path(tempfile.mkdtemp(prefix="nomad-es-migration-")) / "reindex.json"
response_path.write_text(json.dumps(result, indent=2) + "\n")
print(json.dumps(result, indent=2))
print("Reindex response saved to:", response_path)
if not (
    result.get("timed_out") is False
    and result.get("version_conflicts") == 0
    and result.get("failures") == []
):
    sys.exit("Reindex validation failed. Inspect the response before continuing.")

es7_count = request("elastic7", index_path + "/_count")["count"]
es9_count = request("elastic", index_path + "/_count")["count"]
print("ES7 count:", es7_count)
print("ES9 count:", es9_count)
if es7_count != es9_count:
    sys.exit("Document counts do not match. Do not start the app or workers.")
print("Migration verified successfully.")
PY
```

Continue only after the script prints `Migration verified successfully.` It stops on HTTP errors, invalid JSON, reindex failures, or mismatched document counts; an HTTP success alone does not rule out partial reindex failures. If the script is interrupted or fails, inspect ES9's reindex tasks and the destination index before retrying. Do not rerun it blindly: the destination index may already exist, and a reindex task may still be running.

#### 3. Remove the Temporary ES7 Container

Stop and remove only the temporary service, keeping its volume:

```bash
docker compose -f docker-compose.yaml -f docker-compose.es7.yaml stop elastic7
docker compose -f docker-compose.yaml -f docker-compose.es7.yaml rm -f elastic7
```

Continue with [Start the Upgraded Oasis](#start-the-upgraded-oasis). Use only the main Compose file from this point onward. It keeps the migrated ES9 volume and removes the temporary remote-reindex setting when it recreates `elastic`.

### Option 2: Start with a Fresh ES9 Index and Reindex Uploads

In NOMAD, **MongoDB and the archive files (`.volumes/fs`) are the single source of truth**. This option rebuilds the index in the separate ES9 volume and leaves the old ES7 volume untouched. Do not use the ES7 overlay or start ES7 for this option.

#### 1. Start Only ES9 and MongoDB

After completing the preparation steps above:

```bash
docker compose up -d --wait --wait-timeout 360 elastic mongo
```

Compose creates the separate `nomad_oasis_elastic_9` volume. The app, workers, and proxy remain stopped.

#### 2. Run the Indexing CLI Command

Use a one-off container from the upgraded NOMAD app image to index all uploads:

```bash
docker compose run --rm --no-deps app \
  python -m nomad.cli admin uploads index --parallel 4
```

The container uses the app's environment, configuration, and `.volumes/fs` mount. `--no-deps` prevents Compose from starting the app's other dependencies; only MongoDB and ES9 are needed for indexing.

Wait for indexing to finish and check its output for failed uploads or indexing errors. Resolve any errors before starting the remaining services.

!!! tip
    You can increase `--parallel` based on available CPU cores. For large deployments, add `--print-progress 10` to monitor ongoing progress.

### Start the Upgraded Oasis

!!! note
    If startup fails with an error such as `env file /path/to/oasis/.env.north not found: stat /path/to/oasis/.env.north: no such file or directory`, complete the configuration steps in [NORTH Migration for v1.4.3](v1.4.3.md#north-migration) first, then retry startup.

After completing either migration option, start the full stack with only the main Compose file:

```bash
docker compose up -d
docker compose ps
docker compose logs app worker elastic
```

Verify that services become healthy and that existing entries can be searched in the Oasis UI. Keep the old `nomad_oasis_elastic` volume until you have verified the migration. Keeping this volume preserves the old search index, but rolling back the whole installation may also require restoring the old software, configuration, MongoDB backup, and file storage.

Once the migration is verified and you no longer need the old ES7 index, you can optionally remove its volume:

```bash
docker volume rm nomad_oasis_elastic
```
